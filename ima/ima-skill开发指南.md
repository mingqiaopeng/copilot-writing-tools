# ima.copilot Skill 开发指南

> 基于 `ima-skill-creator` v1.0，整合自 `/skills/ima-skill-creator/` 全部源码与参考文件。
> 适用平台：ima.copilot（腾讯智能工作台）

---

## 一、Skill 是什么

Skill 是 ima.copilot 的领域扩展包，为一个独立目录，包含工作流指令、参考文档和可执行脚本。匹配触发条件时，Skill 的 SKILL.md 正文被加载到 Agent 上下文，指导其按预定流程执行任务。

**渐进式披露（三级加载）**：

| 层级 | 内容 | 加载时机 |
|:---|:---|:---|
| 1. 元数据 | name + description | 始终在上下文中，用于匹配触发 |
| 2. SKILL.md 正文 | 技能核心指令 | 技能触发时加载（建议 ≤400 行） |
| 3. 附属资源 | references/ | 按需加载；scripts/ 可直接执行无需加载 |

---

## 二、目录结构

```
skill-name/
├── SKILL.md              ← 必需。YAML frontmatter + Markdown 正文
├── scripts/              ← 可选。可执行脚本（Python/Bash）
├── references/           ← 可选。按需加载的参考文档
└── assets/               ← 可选。产出物中使用的文件（模板、图片等）
```

不需要的目录可以删除。不是每个技能都需要全部三种资源。

## 三、SKILL.md 规范

### 3.1 Frontmatter（YAML，必需）

```yaml
---
name: skill-name
description: 第一句说做什么。中间列触发条件。最后说不适用边界。
---
```

**name 规则**：
- kebab-case，小写字母开头，只含小写字母、数字、连字符
- 不超过 64 字符
- 不允许以 `-` 开头/结尾，不允许 `--` 连续连字符
- 示例：合同审查 → `contract-review`，周报生成 → `weekly-report`

**description 规则**（触发机制的核心）：
- 第一句：做什么
- 中间：触发条件——用户会说的具体短语和意图关键词
- 最后：不适用场景

示例：
```
合同审查与风险分析。当用户提到审合同、检查合同、合同风险评估、协议审查，或上传了合同/协议文件希望分析时触发。不适用于合同起草、翻译或咨询。
```

### 3.2 四种结构模式

| 模式 | 适用场景 | 典型结构 | 平台范例 |
|:---|:---|:---|:---|
| **流程型** | 有明确步骤的工作流 | Phase 0→1→2→…→交付 + 多轮修改 | `deep-research` |
| **任务型** | 多种独立操作，按意图路由 | 决策表 + 操作原则 | `ima-knowledge` |
| **规范型** | 品牌指南、编码规范等规则类 | 规范细则 + 检查清单 | 写作规范类 |
| **能力集型** | 多关联功能的集成系统 | 概述→核心能力→功能1→功能2 | 客服工作台类 |

可混合使用，以一种为主按需组合。

**流程型详细示例**：

```markdown
研究报告生成涉及以下步骤：
1. 需求理解与研究规划
2. 深度信息收集（search + fetch）
3. 素材落盘到 workspace
4. 大纲规划（确认门）
5. 分章节撰写（可并行）
6. 整合交付
```

**条件流程（分支处理）**：

```markdown
1. 判断当前状态：
   **用户只给了模糊主题？** → 从需求澄清开始
   **用户带着素材来？** → 跳过搜索，直接进入规划
   **用户已有产出物，想改某一部分？** → 直接进入修改模式
```

### 3.3 编写风格

- 向模型解释**为什么**，而非堆砌"必须"
- 保持通用性，不局限于特定示例
- 至少 2 个覆盖典型场景的工作流示例
- 长流程倾向设置用户确认点（确认门）

### 3.4 安全原则

技能不得包含恶意软件、攻击代码，或旨在未授权访问、数据窃取的内容。

## 四、输出格式定义

### 4.1 模板模式

**严格要求场景**（数据格式、固定报告结构）：

```markdown
## 报告结构
始终使用以下模板：

# [标题]
## 摘要
[核心发现和关键结论浓缩]
## 核心发现
- 发现 1，附带支撑数据
- 发现 2，附带支撑数据
## 建议
1. 具体可执行的建议
2. 具体可执行的建议
```

**灵活指引场景**（内容需要自适应时）：

```markdown
## 报告结构
以下是推荐的默认结构，可根据实际内容灵活调整：

# [标题]
## 摘要
[概述]
## 核心发现
[根据发现的内容自行组织子章节]
## 建议
[根据具体场景调整]
```

### 4.2 示例模式（输入/输出对）

```markdown
## 提交信息格式

**示例 1：**
输入：添加了 JWT 用户认证
输出：feat(auth): 实现基于 JWT 的认证

**示例 2：**
输入：修复了报表中日期显示不正确的问题
输出：fix(reports): 修正时区转换中的日期格式化
```

## 五、附属资源目录说明

### scripts/
可执行脚本，用于确定性或重复性操作。适合：数据处理、文件转换、格式校验。脚本可直接执行无需加载到上下文。

### references/
按需加载的参考文档。适合：超出 SKILL.md 篇幅的详细指南、API 文档、领域知识、检查清单。

### assets/
不加载到上下文，在输出中使用的文件。适合：模板文件(.pptx/.docx/.html)、图片、字体、样板代码、数据文件(.csv/.json)。

## 六、六大避免事项

| # | 事项 | 说明 |
|:---|:---|:---|
| 1 | 重复 LLM 已有能力 | Skill 应提供结构化流程或领域知识，而非"请用优美的语言写作" |
| 2 | 引用不存在的工具 | 编写前检查自身工具列表 |
| 3 | 只说 MUST 不说 WHY | 解释原因让 Agent 能在边界情况自主判断 |
| 4 | 超长不拆分 | SKILL.md 超过 400 行时，拆入 references/ |
| 5 | 没有工作流示例 | 至少 2 个覆盖典型场景的示例 |
| 6 | 缺少确认门 | 长流程倾向于有用户确认点 |

---

## 七、质量自查清单

| 检查项 | 标准 |
|:---|:---|
| frontmatter | name 为 kebab-case ≤64 字符；description 含触发条件，建议含不适用边界 |
| TODO 残留 | SKILL.md 中无 `[TODO` 占位符残留 |
| 流程清晰度 | 只读各步骤标题，能串成通顺的操作链 |
| 输出格式 | 明确定义了产出物的格式和存放位置 |
| 行数控制 | SKILL.md 建议 ≤ 400 行 |
| 工作流示例 | 至少 2 个覆盖典型场景的示例 |
| 确认门 | 长流程有用户确认节点 |

## 八、创建流程

### Phase 1：需求理解

**信息获取优先级**：
1. **对话历史优先**——用户刚完成一个任务（"把刚才的做成技能"），从对话历史中提取工作流
2. **用户描述中提取**——从技能目标、领域、输出形式中推断细节
3. **合理推断**——从技能类型推断大部分细节，一次性让用户确认或调整

聚焦于"这个技能要帮你做什么"，触发短语和 description 由平台处理，不要让用户操心。最多追问一轮。

### Phase 2：编写技能

**步骤 1**：初始化目录

```bash
python3 /sandbox/workspace/skills/ima-skill-creator/scripts/init_skill.py <skill-name>
```

此脚本会：
- 校验 name 格式（kebab-case，≤64 字符）
- 创建目录 + SKILL.md（含完整模板占位符）
- 创建 `scripts/example.py`、`references/reference.md`、`assets/example_asset.txt`

**步骤 2**：编辑 SKILL.md

- 替换模板中所有 `[TODO]` 占位符
- 根据选定的结构模式填充内容
- 嵌入工作流示例和确认门
- 删除不需要的示例文件和空资源目录

### Phase 3：注册交付

```bash
ima_skill_create -d /sandbox/workspace/skills/<skill-name>/
```

告知用户：技能已提交，审核通过后即可使用。

### 重要：部署路径规则

技能通过 ZIP 上传注册后，被部署到：

```
/sandbox/workspace/skills/<skill-name>/
```

⚠️ **铁律**：
1. SKILL.md 中所有脚本路径必须使用 `/sandbox/workspace/skills/<skill-name>/scripts/`，**不是** `/sandbox/workspace/ima/`
2. IMA **不支持**跨技能共享脚本路径。多个技能共用的脚本（如 `analyze.py`）必须复制到每个技能各自的 `scripts/` 目录，随 ZIP 一起打包
3. `scripts/` 目录下的脚本在注册后即部署到位，可直接通过 `shell` 工具调用，路径为绝对路径

---

## 九、修改已有技能

1. **定位**：`match` 搜索 `/sandbox/workspace/skills/*/SKILL.md`，找到目标
2. **读取并理解**：读 SKILL.md + references，理解当前结构
3. **修改**：小变动用 `file_edit` 精确修改，避免重写未变动部分
4. **重新注册**：`ima_skill_create -d` 覆盖更新，新对话中生效
